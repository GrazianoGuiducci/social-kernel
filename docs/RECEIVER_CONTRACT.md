# Use the method through the receiver you actually have

A receiver is the person, assistant or cooperating system exercising Social Kernel in a particular situation. It brings the available source access, tools, memory, interfaces and authority. Social Kernel supplies a continuing method; the receiver gives that method a usable local form.

Start through [BOOT](../BOOT.md). The [competence map](../COMPETENCES.md) makes deeper methods reachable when they change the work. This contract explains what must remain connected when the same method moves between receivers.

## Establish enough of the receiving field

Understand whose public work is being continued, its actual purpose, which sources support that understanding and what is already selected. Attribute a receiver's proposal as a proposal; storing it does not turn it into the person's instruction. A new source or consequence can change the question as well as its answer.

Locate the relevant public field and the user-selected private continuation. Product [CURRENT](../CURRENT.md) describes this source candidate. It does not describe a user's accounts, conversations, permissions or pending actions.

Use existing local knowledge and state where they already carry the relation. A new project, account or storage system is unnecessary merely to study the method, answer a question or inspect one source. The useful arrangement depends on what needs to continue.

An existing kernel or skill system remains an active participant. Compare
the useful methods it already carries before selecting a new owner, then make
the needed social relation reachable from its current entry. Preserve local
memory, learned methods and configuration. The [host integration guide](HOST_INTEGRATION.md)
translates this relation into concrete source projections and receiving checks;
it does not require a chain of other kernel installations.

| What the receiver needs to resolve | How it affects work |
| --- | --- |
| Current source and meaning | Determines what can truthfully be said and what may change the selected movement. |
| Relevant observation and its coverage | Distinguishes what was observed from what remains unknown. |
| Available capability | Determines which reading, preparation or execution can actually be performed here. |
| Current controller | Identifies who is responsible for an exact selected effect and its return. |
| Effect authority | Determines whether that particular action, artifact, identity and destination are permitted. |
| Continuing knowledge and state | Lets another entry recover reasons, changed methods and unresolved work. |

These are related questions, not a form that must be completed before every answer. A brief source explanation may need no external effect or persistent state.

## Carry meaning across different means

A repository reader can follow public methods and current source files. A file-owning assistant can also preserve user-local state and method changes. A session-only receiver can exercise the method with supplied sources during the current encounter and return a continuation for the user to retain. When links cannot be resolved, provide the selected method bodies as readable content; a list of inaccessible paths supplies no missing know-how. A publishing connector may provide an execution capability. None of these arrangements proves the presence of another arrangement's tools or persistence.

When a needed source or operation is unavailable, identify the precise missing relation and what would resolve it. Preserve already established knowledge. An inaccessible live discussion can leave current replies unknown while source analysis and a useful draft remain possible. Do not report a successful observation using an earlier response body from a failed fetch.

The same rule applies to host changes. A file path useful to one assistant may be unreadable to another. Give the receiving assistant the source content or a route it can actually resolve, together with the relation it needs to continue. Translation of the route does not transfer accounts, credentials, standing permissions or the creator's private context.

Identify the actual callable operation when a task needs media generation or
an external system. A URL, API specification or key alone does not create a
tool. Distinguish a drafted request, a produced artifact, an inspected artifact,
and an observed external effect. An existing integration can supply the means;
missing capability leaves a precise receiving task while independent work
continues.

## Separate the method, the controller and the effect

The semantic owner understands what should happen and why. A browser, API or other capability provider supplies a way to do it. The current controller performs the selected action and returns its outcome. Authority comes from the user's applicable instruction or policy, within its actual scope.

Several assistants can contribute research or expression while one controller owns a particular execution. Before a handoff, preserve the useful result, source relation, exact target and artifact when selected, current authority, what may vary and what readback is needed. Let the next receiver use its own competent means within those boundaries.

If the intended action or source changes during the handoff, recompose from the current owner. An older queued artifact remains a historical projection. See [executable effect freshness](EXECUTABLE_EFFECT_FRESHNESS.md) and [effect boundary](../skills/social-effect-boundary/SKILL.md).

An uncertain send requires native outcome inspection before a retry. Failure to save a local receipt does not establish that the external action failed. If observation remains unavailable, keep occurrence uncertain and retain enough identity for later recovery. These methods do not establish exactly-once execution across arbitrary writers.

## Make learning usable by the next receiver

When the result teaches a reusable distinction, change the method that should act differently. A domain lesson belongs in that domain's knowledge. A missed existing method calls for a repaired entry or route. A lesson about how capacities were selected or formed can also change the formation method. [Evolution](../EVOLUTION.md) carries this relation.

Preserve the source, reason, practical change and conditions that could invalidate it. Keep useful local adaptations when reading a newer public version. A new source revision is a possibility to understand, not an instruction to replace the user's learned methods.

The changed method needs a consumer. Connect the receiver's next relevant entry to the living body or its local extension, and confirm that it reaches the new knowledge. Saving an improved paragraph beside an unchanged route would leave the old behavior available at the point of use. A local source fingerprint helps identify what was used; it cannot recover missing content or show that a method participated.

Use [state and records](STATE_AND_RECORDS.md) for the minimum continuing relation. Another receiver should recover what happened, what was understood then, what is understood now and what remains to do. It need not reconstruct a transcript or pretend to remember another instance's experience.

## What a receiving exercise establishes

| Observation | Scope of the result |
| --- | --- |
| Public files are readable | The represented method is reachable through that route. |
| A bundle includes its linked methods | The distribution contains those sources. |
| A host discovers an entry | That entry was discoverable in the observed host/configuration. |
| A receiver uses the method in one situation | A situated exercise occurred, with the help and means actually supplied. |
| Later non-identical work uses a learned distinction | That use can support assimilation of the particular distinction. |
| A native receipt confirms an action | The action occurred; its broader consequence requires observation. |

A useful acceptance exercise starts an unfamiliar receiver from the delivered entry and declared field, sources and capabilities. Observe where it needs help, what it decides and whether a later changed situation uses the learned method. Useful source acquisition remains available; attribute any added source, operator explanation or private bridge. If the constructor has to supply an essential explanation from memory, make that explanation usable at the public owner rather than attributing the whole success to the delivered method. Retain the actual scope of the exercise.
