## Purpose

Install a persistent operating method for public presence into ChatGPT/Codex.

The first plugin does not need direct social APIs to be useful.

It can already guide:
- public-field reentry;
- opportunity/no-action formation;
- source-aware expression;
- event/consequence readback;
- relationship continuity;
- user-field projection;
- cognitive-integrity handling;
- learning return.

## Public boundary

User/project private knowledge stays local or in the user's selected MAIOS
continuum.

A surface tool receives only the smallest pertinent projection.

No plugin installation creates standing authority to publish, message, spend or
change an account.


## Naming / product-boundary correction — 2026-10-03

The first private OpenAI package remains useful as a **Social Kernel skills-only
probe A0**.

It is not yet the public product package.

Current relation:

~~~text
K-Social
  private living source / operator-specific formation

Social Kernel
  generalized public semantic product

maios-social-kernel private probe
  first OpenAI skills/activation experiment

MAIOS ChatGPT Adapter
  current private host adapter
  may enter K-Social and compose external capability providers

future Social Kernel for ChatGPT
  generalized public receiver adapter derived from exercised private learning
~~~

The private probe should not be treated as the final public naming or
architecture.

The current preferred development path is:
1. exercise MAIOS ChatGPT Adapter against real K-Social work;
2. observe which social functions genuinely belong in the receiver adapter;
3. distinguish semantic method from external publisher/analytics/browser
   capability;
4. return reusable learning to K-Social / Social Kernel / plugin-incarnation
   owner as appropriate;
5. only then form the public Social Kernel for ChatGPT package.

External plugins/connectors may participate as capability providers in private
operation. They do not acquire Social Kernel semantic ownership.
