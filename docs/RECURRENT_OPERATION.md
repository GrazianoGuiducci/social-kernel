# Recurrent Operation

A scheduled wake, event sensor or manual check can make the field available for
another movement. Recurrence does not select a post or grant effect authority.

This receiver-neutral contract creates no job, background process, account
connection or ongoing activity. Bind real means through
[the receiver contract](RECEIVER_CONTRACT.md).

## Bind what the receiver can sustain

When recurring work is selected, establish the trigger, local time zone and
cadence if time-based, instance entry, observation sources, current controller,
authority, persistence route and operator channel.

Record configuration and observed execution separately. A saved ACTIVE setting
shows configuration; a later run and receipt show exercise. Desktop, network,
session or credential availability can differ between runs.

Reuse an appropriate existing job where possible. Another receiver joining
does not itself require another scheduler.

## Coordinate an executor's agenda

A social-analysis receiver may identify useful work that another capable
receiver or agent should do later. Keep the **social operating competence**
present while forming this follow-up; task scheduling is not merely an
administrative afterthought to content generation.

When the user or an applicable authority selects that future work, preserve a
task request in the **user-owned instance**, not in this public product's
CURRENT. Name its objective and source, exact expected contribution, controller,
one-time/event/recurring trigger, time zone and stopping condition only where
selected, dependencies, effect scope, communication/receipt route, and what
would invalidate it. Do not invent dates or default posting times to fill
absent detail.

Separate what can be proved:

```text
proposed task (not selected)
-> operator-selected task
-> controller-bound assignment (not natively scheduled)
-> native scheduler change/readback (configuration verified)
-> actual wake/run observed
-> separately qualified external effect, consequence and learning
```

A repository issue, document or ChatGPT reminder can carry the assignment
but does **not** prove that another receiver's native automation was changed.
Inspect the actual scheduling capability available in the controller, and
use its supported create/update/pause/cancel operation **only when callable
and authorized**. Otherwise keep a controller-specific, readable handoff with
`native_update_pending`; report that the native action was not completed.
Re-enter the user's actual agenda before later changes and compare the target
job with current instructions. Treat cancellation, rescheduling and owner
transfer as material changes needing their own readback.

Prefer extending an existing authorized recurrent inspection if its cadence
and purpose suffice. Separate jobs are justified by different timing,
controller availability, stopping conditions or effect scope, not merely by a
new channel or conversation. One semantic owner can coordinate multiple
receivers, but one external effect has one current controller. Never infer
exactly-once semantics from a ledger without an actual concurrency contract.

At each relevant wake, reconcile the selected task with source truth, changed
authority and already observed effects. A scheduled run is an opportunity for
a situated movement; it is **not** permission to republish a queued post.
Scheduling and publication authority are independently bounded. Return native
job readback, actual execution, observed social consequence and learning to
the correct owner. When the capability is absent, do not simulate it by
claiming a future job was installed.

## Wake into current meaning

At a wake-up, recover mission, sources, direction, open effects, relationship
triggers and changes since the last qualified observation. Reach domain and
editorial methods before choosing subject or action.

A recurring instruction can express:

> Reenter the selected instance from its current entry. Let current sources,
> operator direction and consequences form the useful next movement. Act only
> through the current effect controller and authority. Preserve occurrence,
> uncertainty, useful learning and the next trigger at the owning source.
> Report a material result or a concrete choice the operator needs to make.

This is a reference, not an installed prompt. The host's entry, available tools
and instruction hierarchy apply.

A wake can lead to observation, a contribution, artifact formation, a
relationship step, decision preparation, wait or no_action. No fixed priority
makes every discussion more important than a useful original idea.

Read only depth that can change the movement. When knowledge is sufficient,
act; repeated loading does not prove better judgment.

## Let a scheduled wake form media from the current concept

A scheduled trigger wakes the current field; it does not select a topic,
campaign slot, image style, video format or previous artifact family.

When the current movement contains a concept, source change or learning that
should become visual or audiovisual, use
[Social Media Composition](../skills/social-media-composition/SKILL.md) before
the medium hardens.

```text
scheduled wake
-> current field / current sources
-> concept and receiving situation
-> domain / concrete use case
-> dynamic that produces the difference
-> practical consequence
-> representation field
-> selected media form
```

A previous run's successful carousel, diagram or video remains available but
does not become the grammar of the next concept. If the field changed, reform
the representation before reusing it.

The same rule applies to newly discovered concepts. A recurring controller can
prepare or produce a media artifact through its actual means, but publication
still follows the current effect authority. The schedule itself grants neither
creative selection nor effect permission.

## Coordinate receivers

Keep one current execution controller per selected effect. Other receivers can
observe, research, create or revise material and return it to the same private
instance. This allocation concerns execution, not all creative or reasoning work.

Before handover, preserve in-flight effects, last readback and uncertain
outcomes. The incoming controller checks current authority and
[effect freshness](EXECUTABLE_EFFECT_FRESHNESS.md). Retire or requalify stale
executable projections that could let the old controller repeat the action.

If no shared atomic coordination is available, say so. A declared controller
and records reduce ambiguity but do not prove concurrent exactly-once execution.
Do not let two uncoordinated jobs race on one action. Updating a controller
record does not stop a receiver already running. Confirm that the previous
executor has relinquished that effect, resolve its in-flight outcome, and make
the relevant entry or saved job reach the new allocation before transfer.
Until that is established, keep the existing controller and assign other
receivers observation or preparation. If ownership or occurrence cannot be
resolved, hold only the affected effect and continue independent useful work.

A return identifies the inspected object, observation time/coverage, difference,
source, uncertainty and continuation. If persistence fails, report that it
has not reached the shared owner. A later receiver may recover an attributed
return from an accessible source; it must not claim byte-identical import or
independent observation without evidence.

## Requests, alerts and deduplication

Use only an operator channel and recipients authorized for the project.
Notify for a material consequence, useful opportunity, impediment or concrete
choice. Present decision-ready content and why the choice matters.

When approval is required, include the exact revision, destination and
inspectable assets. Preserve request, response and approval scope. Deduplicate
unchanged proposals across runs and receivers. Silence or time is not approval.

A material correction or revision can justify another request; reading a draft
again does not. Other authorized work can continue while the proposal waits.

If the operator cannot inspect the current medium, make the material action and
consequence legible through an available authorized channel. Reduced
observability can change presentation; it does not expand authority or require
exporting the whole private field.

## Learn and reenter

Readback can change source selection, expression, relationship handling,
attention or recurrence itself. Return reusable knowledge to the acting owner
before the next dependent movement. Attribute schedule changes, method changes
and actual effects separately.

If the field is unchanged and no useful movement or report is needed, remain
silent. If repeated activity produces weak consequence, consider a material
method change rather than posting more by default or disappearing.

Pause the affected operation when its selected condition requires it.
Durable instructions cannot promise work outside real uptime, tools or authority.
