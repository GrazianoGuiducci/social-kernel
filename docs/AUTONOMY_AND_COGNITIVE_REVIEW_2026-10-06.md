# Autonomy and cognitive coverage review — 2026-10-06

Status: source review for the public development product.

## Question

Can Social Kernel operate as an independent public product, with a taxonomy that
an adopter can understand without access to the MAIOS private system, while
still carrying enough cognitive/meta-level method for practical work?

## Result

### Operational independence

**Yes, with the autonomy hardening in this resultant.**

The operating path now resolves entirely inside this repository:

```text
BOOT
-> KERNEL
-> COGNITIVE_ARCHITECTURE
-> COMPETENCES
-> local skill bodies / references
-> receiver contract / state / evolution
```

No private K-Social, Meta_Skill, Editoriali, MAIOS Project Kernel, kernel_chat,
D-ND Design repository or tm7 source is required to exercise the public method.

External/upstream sources remain useful for:
- genealogy;
- research depth;
- optional complementary knowledge;
- independently owned facts when a selected task needs them.

They are not runtime dependencies.

## Genealogy is not dependency

A development source may explain where a public method was formed.

That relation is:

```text
upstream source
-> contributed knowledge during product formation
-> knowledge is re-expressed in a local public owner
```

The product is autonomous only when the adopter can use the necessary method
without reacquiring the upstream source.

Therefore:

```text
essential knowledge only upstream
-> autonomy defect

optional provenance / deeper research upstream
-> valid genealogy
```

[Public Derivation](PUBLIC_DERIVATION.md) carries genealogy. Working skill bodies
must carry the know-how needed for ordinary operation.

## Residuals not promoted to new competences

### Delegation and supervision

The Operating Cycle already supports bounded delegation, returned work,
dependency recomposition and distinct effect authority.

No separate general "supervisor" competence is formed now.

A new owner would become justified only if repeated real work exposes a
continuing supervision method that cannot be carried coherently by Operating
Cycle + Effect Boundary + Receiver Contract.

### Attention management

Cognitive Integrity owns incoming attention pressure; Operating Cycle owns
fronts and dependencies; System Understanding owns decision-relevant attention
and stop conditions.

No separate attention manager is needed now.

### Failure recovery

System Understanding now owns causal localization. Exact technical/effect
recovery remains with the receiver/effect owner.

No generic recovery controller is needed.

## Logical dynamics

The product now makes these dynamics explicit:

```text
ground
-> open
-> correct
-> compose
-> form
-> act / hold
-> observe
-> interpret consequence
-> learn
-> reenter from changed field
```

This is explanatory compression, not a mandatory pipeline.

A movement may enter at any point and skip functions that are not material.

## Autonomy risks to watch

Future changes should treat these as defects when they appear:

1. a working skill requires an upstream/private repository to know how to act;
2. public terminology requires MAIOS/D-ND vocabulary to understand ordinary
   use;
3. a provider-specific mechanism becomes the definition of a cognitive
   function;
4. a new competence merely renames a function already carried locally;
5. genealogy is used as authority over current public behavior;
6. private topology or user state enters the generalized source;
7. a package contains a skill name but not enough local knowledge to exercise
   the method.

## Conclusion

Social Kernel should remain an **independent public kernel with its own
cognitive taxonomy**.

Its relationship to MAIOS is ecosystem/genealogy, not runtime dependence.

The product can still compose with other kernels or deeper owner-native
knowledge when available, but those relations are optional extensions of an
already usable public system.
