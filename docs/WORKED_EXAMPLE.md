# A public answer that changes the next answer

This is a fictional example. Fieldnote, its operator Alex, its features, the community and every quotation below are invented. No post, relationship, user trial or external product result is reported here.

The example follows one useful relation across two different encounters: a true feature statement can still leave the reader unable to judge whether it serves their purpose. A consequence teaches the expression method to connect the reader's intended action with what the actual destination supports.

For the story, Alex's starting local method checks release truth but has not yet made that reader-action relation explicit. Current Social Kernel already teaches this relation. A receiver using it should preserve a good initial answer instead of reproducing the story's omission to make learning visible.

## The starting field

Alex maintains Fieldnote, a small toolkit for community organizers. Their stated purpose is to help volunteer groups move and coordinate their work. The current source describes a released CSV export of text notes. Attachments and discussion replies remain outside that export. The user-selected private field holds the source references, the purpose and prior conversations.

In a fictional community discussion, an organizer asks how to move several years of activity to another tool. Alex selects a public response. In this scenario Alex explicitly authorizes the exact reply and destination; that invented authorization applies only within this example.

The receiver reads the release source and prepares:

> Fieldnote exports workspace notes as CSV. The guide explains how to run the export and read the file.

This statement matches the source's feature description. In the story Alex publishes it and the field records the exact reply and target. That record establishes occurrence within the scenario; it says nothing yet about whether the response met the reader's need.

## A consequence changes what matters

The organizer responds:

> Does that include the attachments and replies? Those are most of our history.

The new response makes the reader's intended object more precise: migration of a whole shared history. The first answer correctly named an available feature, but it did not connect that feature's limits to the work the reader wanted to perform.

The receiver preserves both relations. It does not rewrite the first statement as knowingly false, and it does not defend it as sufficient merely because its words were technically accurate. It returns to the source, distinguishes what is exported and prepares a useful continuation:

> The CSV contains text notes. Attachments and discussion replies need a separate transfer, so this is one part of your migration. The guide's inventory step will help you identify what remains before you move anything.

The inventory step is another explicitly assumed source fact in this fictional example. The receiver does not invent a missing migration capability. Alex can authorize this exact continuation under the scenario's current policy.

## Teach the method that selected the answer

Saving the organizer's question is useful relationship history. Saving the revised draft is useful artifact history. The reusable lesson belongs in the receiver's source-to-expression method.

The recipient's local [surface-expression](../skills/social-surface-expression/SKILL.md) knowledge now carries this practical distinction:

> Before inviting a reader to use a feature, connect the action the reader is trying to perform with what the linked destination actually lets them do. Check material omissions and prerequisites against the source. A correct feature description can support only part of a larger task. Explain that relation at the reader's useful level, and offer another source-supported next step when one exists.

The method also retains why this distinction emerged, the source of the feature limitation and the conditions that could change it. If a later release adds attachments and replies, the old limitation becomes history. The broader reader-action question remains useful where the situation makes it pertinent.

The local current entry points to the changed method and the still-open migration conversation. The receiver's expression route actually reads that living body or local extension; a saved note with no consumer would not complete the change. Deeper knowledge remains in its owning body or reference. A new receiver can reach it without receiving Alex's entire private history.

This is a change in expression and source selection. If examination showed that the knowledge already existed but the entry failed to reach it, the repair would instead belong in that route. [Competence evolution](../skills/social-competence-evolution/SKILL.md) distinguishes these cases; a new skill is not needed for every lesson.

## A later, non-identical encounter

Another organizer later asks:

> Can three coordinators update this planning board together?

This concerns collaborative planning, not migration. In the scenario a public directory describes Fieldnote's board as a collaboration tool. The maintained source says that the public board is a read-only demonstration; a linked shared worksheet is the editable tool. These facts are provided as part of the fictional starting conditions for this second encounter.

A receiver entering through the revised method asks what the organizer needs to do at the destination before choosing the demonstration as its answer. It gives:

> The public board is a read-only example. For joint editing, use the shared worksheet linked in the guide. The board shows the layout you can reproduce there.

The learned distinction changes an observable decision: the receiver offers the editable worksheet for the requested action and positions the demonstration according to its actual role. A reply that only said "Fieldnote includes a planning board" would leave the same practical gap as before.

The directory remains evidence of how someone represented the product. In the supplied conditions, the maintained product source grounds the account of what the destination supports. If relevant direct use later contradicts it, the receiver must investigate and qualify that account; source ownership is not infallibility. Neither the directory label nor a source's recency alone substitutes for understanding that capability.

## What continues from both encounters

| Continuing relation | What the recipient preserves |
| --- | --- |
| First occurrence | The original answer, its source and what it accurately stated at that time. |
| First consequence | The organizer clarified that their migration includes attachments and replies. |
| Current interpretation | Feature truth must be related to the reader's intended action to form a useful invitation. |
| Method change | The expression method now checks that relation before selecting its claim and destination. |
| Later use | In the planning encounter, the receiver chooses the editable worksheet and qualifies the demonstration. |
| Remaining unknown | Whether either organizer uses the suggested material or finds it helpful. |

The learning can remain useful even if no public engagement count changes. It changes how work is understood and what answer is produced. A later encounter can deepen or invalidate its current form.

## Exercise the example without inventing evidence

Give a receiver the starting facts, BOOT and the linked public methods. Let it work through the first encounter and the later condition. Inspect the actual answer, the owner of any learned difference and the second decision. A receiver may produce a better initial answer and have no need for this particular correction; record what happened instead of forcing the story.

This exercise can reveal unclear entry, missing know-how or a useful alternative. It remains a fictional/local exercise. Structural validation can check references and source delivery, while a receiver exercise can show the decisions it made under the supplied conditions. Neither establishes real publication, independent adoption or universal assimilation.
