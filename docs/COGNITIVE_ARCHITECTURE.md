# Cognitive architecture

Social Kernel is a self-contained public operating kernel. Its cognitive
functions are expressed in ordinary operational language so an adopter does not
need prior knowledge of MAIOS, D-ND or the private system that produced it.

This document is a map of **functions**, not a mandatory sequence.

## Cognitive core

### 1. System understanding

Question:

> What is the actual field, and is our current interpretation still faithful to
> it?

Owner:
[Social System Understanding](../skills/social-system-understanding/SKILL.md)

Functions:
- source / intent / interpretation distinction;
- open possibility without reopening valid determination;
- in-flow correction of receiver-introduced distortion;
- capability / competence / authority discrimination;
- representation adequacy;
- temporal-causal reasoning;
- failure localization;
- attention and stop conditions.

### 2. Reentry and continuity

Question:

> What still matters from previous work in this present?

Owner:
[Social Field Reentry](../skills/social-field-reentry/SKILL.md)

Functions:
- recover current sources, effects, relationships and authority;
- preserve attribution and applicability;
- avoid replaying stale state;
- return a compact usable present.

### 3. Competence composition

Question:

> Which knowledge and method must participate for this movement?

Owners:
[Social Kernel Operating Cycle](../skills/social-kernel-operating-cycle/SKILL.md)
and [Social Competence Evolution](../skills/social-competence-evolution/SKILL.md)

Functions:
- make pertinent competences participate while the question forms;
- distinguish missed discovery, shallow method, missing capability and genuine
  competence gap;
- reuse, deepen, compose or form the smallest continuing method;
- let useful learning alter future competence formation.

## Logical dynamics

The kernel can be understood through a few reusable dynamics.

### Grounding

```text
source / direction / observed field
-> situated understanding
```

### Aperture

```text
situated understanding
+ still-reachable possibilities
-> no premature closure
```

### Correction

```text
developing interpretation
+ source/object mismatch
-> return to faithful relation
-> corrected movement
```

### Composition

```text
current movement
+ pertinent competences / actual capabilities
-> useful method and action
```

### Effect

```text
selected result
+ real controller
+ current authority
-> external action or explicit non-action
```

### Consequence

```text
event
+ later observation
-> qualified changed field
```

### Learning

```text
qualified consequence / useful result
-> closest reusable owner changes
-> later work begins differently
```

### Continuum

```text
changed field
-> recoverable current relation
-> next movement
```

No single diagram, database, agent or runtime owns these dynamics.

## Composable kernel field

Social Kernel's cognitive architecture is complete enough for standalone use,
but it can participate in a wider harness of independent kernels.

```text
standalone kernel
+ optional compatible kernels
+ operator harness
-> situated composition
```

Composition is function-driven. Another kernel participates when its knowledge
changes the result, not because an ecosystem catalogue lists it.

General kernels such as MAIOS Project Kernel or kernel_chat can provide broader
continuity/operating relations. Specialized kernels can contribute domain or
product knowledge. All retain their own identity and learning.

See [Kernel Ecosystem Composition](KERNEL_ECOSYSTEM_COMPOSITION.md).

## Practical autonomy

An independent Social Kernel installation needs only:

- this public source or a self-contained projection of it;
- a receiving AI able to read the method;
- the user's selected context/sources;
- whatever real tools and persistence the selected work requires.

It does **not** require:
- MAIOS Project Kernel;
- kernel_chat;
- Meta_Skill;
- private K-Social;
- Editoriali;
- D-ND Design Kernel;
- a private MAIOS repository.

Those systems can contribute additional knowledge when available, but the
public kernel contains the operating knowledge needed for its own work.

## Genealogy vs dependency

The project retains [Public Derivation](PUBLIC_DERIVATION.md) so people can
inspect where some ideas were developed.

A provenance link means:

```text
this source helped form the public method
```

It does not mean:

```text
the source must be installed or reachable for the method to work
```

If essential know-how is discovered to exist only in an upstream source, that
is an autonomy defect: carry the required knowledge into the appropriate
Social Kernel owner rather than silently depending on the upstream source.
