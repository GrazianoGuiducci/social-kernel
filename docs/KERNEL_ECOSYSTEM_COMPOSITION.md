# Composing Social Kernel with other kernels

Social Kernel is an independent public kernel.

It can be used by itself, or integrated into an operator-controlled harness
where other independent kernels are also reachable.

## Standalone use

A standalone receiving environment needs only:

- this Social Kernel source or a self-contained projection;
- the user's selected context and sources;
- the receiving AI's actual persistence and tools;
- any account/controller access needed for selected external effects.

No MAIOS Project Kernel, kernel_chat, private K-Social or other MAIOS product is
required for ordinary Social Kernel operation.

## Composed use

A harness can make several kernels reachable at the same time.

```text
operator / current field
+ reachable independent kernels
+ actual receiver capabilities
-> identify the functions that matter
-> let one or more kernels participate
-> keep their identities and owners distinct
-> form one situated result
-> return reusable learning to the kernel that should change
```

Composition is optional.

A second kernel should participate only when its knowledge materially changes
the work.

## General kernels

Two general MAIOS kernels can provide broader operating continuity when useful.

### MAIOS Project Kernel

Useful when the AI works inside a durable project/workspace/filesystem and needs
a general project operating kernel around specialized domain/product kernels.

It can contribute project context, knowledge continuity, competence formation,
coordination and host adaptation.

### kernel_chat

Useful when continuity must remain portable across conversational or lighter
receiving environments through a durable source and compact operating entry.

It can contribute general continuity, competence and evolution without requiring
a project workspace.

Neither is required by Social Kernel.

If both are reachable, use both only when their roles are materially distinct in
the actual harness. Do not create parallel owners for the same function.

## Specialized kernels

A specialized kernel can contribute a bounded field of knowledge and method.

Social Kernel contributes public/social work.

Another domain or product kernel can contribute its own domain understanding,
sources, methods and product-specific continuity.

A composed movement could look like:

```text
domain/product kernel
+ Social Kernel
+ optional general kernel
+ operator harness
-> domain-grounded public work
```

The result does not merge the kernels into one identity.

## Harness responsibilities

The harness may provide:

- source/kernel discovery;
- persistent context;
- tool and connector routing;
- filesystem or project access;
- model access;
- account/controller bindings;
- execution mechanisms.

The harness supplies reachability and capability. It does not automatically
become semantic owner.

Effect authority still comes from the operator or applicable policy.

## Preserve ownership

Keep distinct:

```text
kernel identity
kernel source
user/instance state
receiver/harness capability
acting account/controller
effect authority
```

One kernel's presence does not grant another kernel access, state or authority.

When several kernels teach the movement, return each reusable difference to the
owner whose later work should change.

## Discovery is not activation

A product catalogue, manifest or harness inventory can tell the receiver that a
kernel exists.

Keep distinct:

```text
known
!= reachable
!= discovered by this receiver
!= pertinent now
!= participating
!= assimilated
```

Do not load every available kernel into active context.

## Product awareness

Social Kernel should be able to tell an adopter:

> You can use Social Kernel by itself. If your AI environment already uses
> other independent kernels, Social Kernel can join that harness and contribute
> its public/social methods without replacing the other kernels. MAIOS Project
> Kernel and kernel_chat are optional general kernels that can provide broader
> continuity when their receiving relation fits your environment.

This is an ecosystem possibility, not an installation requirement.

## Future interoperability

If real multi-kernel harness work later shows that machine-readable kernel
discovery or a shared interop profile changes routing materially, that function
can be formed then.

Do not introduce a central registry or fixed composition protocol merely because
several kernels exist.
