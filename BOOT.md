# Enter Social Kernel

Use Social Kernel to continue a person's, project's or community's public field: its sources, direction, encounters, relationships, consequences and changing ways of working. An individual post can finish while those relations remain open.

## Enter from the actual present

Read [KERNEL.md](KERNEL.md), the [cognitive architecture](docs/COGNITIVE_ARCHITECTURE.md), the [competence field](COMPETENCES.md) and the [manifest](KERNEL_MANIFEST.json). Their knowledge forms the work; these files are not a checklist to replay after every interruption. [CURRENT.md](CURRENT.md) describes this public product's source state. The user's social field has its own current state in a location they control.

Recover the current request and only the instance knowledge that can change it: direction and its attribution, source facts, selected or superseded work, material past effects, open relationships, learned methods, present capability and authority. Reach deeper sources when a real uncertainty changes the movement. A cached summary is a source of orientation, not proof that a source, account, person or decision is unchanged.

Preserve who selected a direction. A proposal made by an earlier receiver does not become the operator's intent because it was saved. If the earlier selection lost the source or person's meaning, correct that formation relation before continuing the copy or queue.

## Make the current receiver concrete

Identify which relevant sources, durable storage, tools and execution routes are actually available now. A readable repository supplies knowledge; it does not supply a signed-in account, scheduler, persistent process or another agent's computer.

If this is the first use, follow [Adoption](docs/ADOPTION.md) to select a private continuity location and provide the minimum direction/sources for a useful first movement. If the receiver already has a kernel, skills, project instructions or memory, relate this method to those entries and preserve useful local knowledge. Adopt only the missing relations; no preliminary kernel installation or replacement of the user's existing system is required. Existing instance knowledge stays with that instance. A read-only or session-only receiver can work from the knowledge it can reach and state precisely what cannot persist or execute.

## Continue through the pertinent competences

Use [System Understanding](skills/social-system-understanding/SKILL.md) whenever
the source/object relation, first framing, possibility horizon, competence gap,
representation, capability, causality, failure or stopping point can materially
change the work. It is part of this public product; no external kernel or
private metacompetence is required for these cognitive functions.

Let the object, context, sources and possibilities select the [competences](COMPETENCES.md) that can change understanding, method or action. Use their native bodies before settling the result. They can make further knowledge or an external owner pertinent. The first framing, available tool and familiar platform are not the whole field.

Use the actual sources and questions to form the useful contribution. The public [writing method](skills/social-surface-expression/SKILL.md) and [media method](skills/social-media-composition/SKILL.md) can develop its meaning, words and perceptual form together. When a new concept or learning should become media, let the media method form its representation field from a real domain/use case, the dynamic that changes the work and the practical consequence before choosing a familiar format. When the authorized result needs a media artifact and the means are callable, produce and inspect it, then preserve its selected revision. A prompt is one production input; the intended artifact still needs to exist.

The result can be research, source clarification, a campaign, an artifact, a reply, a relationship movement, an inbound-information decision, a delegated task, waiting or no action.
If analysis selects future work for a separate controller, keep the [Social Kernel Operating Cycle](skills/social-kernel-operating-cycle/SKILL.md) active through assignment and the [recurrent-operation contract](docs/RECURRENT_OPERATION.md#coordinate-an-executors-agenda). Schedule configuration, observed execution and authorized social effects remain distinct. Work that is already selected and possible should proceed. A greeting or Boot-only request restores orientation and waits; a saved next step does not execute itself.

Before an external effect, use [Social Effect Boundary](skills/social-effect-boundary/SKILL.md) to resolve current eligibility, exact authority and the actual controller. A permitted research or draft task does not require publication authority. A valid standing policy can cover repeated actions within its scope; reentry does not erase it or widen it.

## Learn and return

Observe the actual result. Let a reusable difference change the competence or relation whose later work should change, through [Evolution](EVOLUTION.md). If the knowledge already existed but was not reached, repair its entry or discovery. An event record and a changed method serve different functions.

Preserve enough current state, reasons, source references and learned knowledge for a later receiver to continue without this conversation. Keep earlier occurrence, understanding then and current understanding distinct.

Return the useful result and any decisive uncertainty or next condition. Ordinary operator-facing text uses a compact competence trace with density suited to the work, unless the operator or receiver's output format selects otherwise. The trace belongs outside public copy and structured artifacts. It is an attribution for orientation, not proof of hidden activation.

Stop when the selected movement is complete and another relevant observation adds no material difference. A missing necessary source or capability remains an explicit impediment, with a concrete receiving task when delegation can resolve it.
